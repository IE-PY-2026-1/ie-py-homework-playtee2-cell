## 🟩 [2차 과제: V1.0] 입출력 + 리스트 + 조건문 - 향후 작성 예정
### **✨2차 과제 내용:**

  * 이번 과제는 사용자로부터 닭가슴살 제품 정보와 식단 데이터를 입력받아 리스트에 저장하고, 복합 조건문을 통해 식단의 효율성을 진단하는 '정밀 영양 판독 시스템'을 구축하는 것입니다. 특히 if-elif 조건문과 and/or 논리 연산자를 활용하여 상황에 맞는 식단 등급과 특별 칭호를 부여하는 지능형 로직을 완성해야 합니다.
  * input() 함수를 사용하여 제품명, 중량, 단백질 함량(g), 가격(원)을 연속으로 입력받아 하나의 리스트 자료형으로 묶어서 저장합니다.
  * 입력된 리스트 데이터를 바탕으로 가중치 공식을 적용하여 종합적인 '단백질 가성비 지수'를 산출합니다: (단백질 함량 * 1.5) / (가격 * 0.1) 등
  * and 및 or 연산자를 활용하여 "단백질 함량이 25g 이상이면서(and) 가격이 2000원 이하"일 경우 '득근 마스터' 등 특별 칭호와 맞춤형 피드백을 부여하는 기능을 구현합니다.
  * if-elif-else 구문을 사용하여 산출된 가성비 지수에 따라 S등급(최상급 식단)부터 F등급(영양 불균형)까지 5단계 식단 효율 판정 로직을 추가합니다.

### **🛠️ Troubleshooting & 기술 회고:**
(예시) 
1. **문제 1: 복합 조건문에서 엉뚱한 등급이나 칭호가 부여되는 현상 (Logic Error)**
    * **원인:** if-elif 조건문 작성 시 조건의 순서를 고려하지 않아, 'S등급' 조건에 부합하는 데이터가 상단에 잘못 배치된 'A등급' 조건에 먼저 걸려버리는 논리적 헛점이 발생함.
    * **해결:** 해결: 조건이 가장 까다로운(가장 범위가 좁은) 최상위 등급과 특별 칭호 조건을 if문의 맨 처음에 배치하고, 점차 범위를 넓혀가며 elif를 작성하는 하향식(Top-down) 검사 구조의 중요성을 학습하고 조건문 순서를 재배치하여 해결함.
2. **문제 2: 리스트에서 데이터를 꺼내 계산할 때 발생하는 에러 (TypeError)**
    * **원인:** input()으로 받아 리스트에 저장한 데이터는 기본적으로 '문자열(str)'이므로, 리스트 인덱싱을 통해 단백질 함량과 가격을 꺼내어 곱셈/나눗셈을 시도할 때 연산 불가 에러가 발생함.
    * **해결:** append() 하기 전, 혹은 연산을 수행하는 시점에 int()와 float() 함수를 사용하여 숫자형 데이터로 알맞게 '형변환(Type Casting)'을 거치도록 코드를 수정하여 해결함.

  1. **문제 1: for문을 통한 2차원 리스트 순회 및 필터링 시 발생하는 인덱스 범위를 벗어난 에러 (IndexError)

     * **해결: for 반복문이 작동할 때 추출되는 product 변수 자체가 하나의 독립된 제품 정보 리스트임을 중간 print() 출력을 통해 확인했습니다. 이후 개별 리스트 내부의 정확한 영양 성분 인덱스 번호를 지정하여 다중 조건 필터링 시스템이 에러 없이 완벽하게 구동되도록 하였습니다.
   2. **문제 2: 함수 내에서 전역 리스트에 데이터를 누적할 때 발생하는 참조 오류(데이터 누락)
      * **원인: 메인 메뉴에서 '1. 입력'을 선택했을 때 실행되는 데이터 입력 함수 내부에서, 프로그램 전체의 데이터를 담는 전역 변수(General List)에 append()를 하여 총단백질 양을 누적시키려고 하였습니다. 그러나 함수 내부에 마법의 기호인 global 키워드를 명시하지 않아, 이를 함수 내부에서만 쓰이는 '지역 변수'로 오인하여 데이터가 메인 루프에 저장되지 않거나 참조 오류가 발생했습니다.
      * **해결: 데이터를 추가하고 수정하는 함수 상단에 global chicken_database 형태로 전역 변수를 명시하여, 이를 통해 함수 내부에서 일어난 데이터 추가 및 누적(+=) 연산이 프로그램 전체 데이터베이스에 안전하게 영구 반영되도록 구조적 결함을 해결했습니다.

### **🛠️ Troubleshooting & 기술 회고:**
  1. **문제 1: 입력값 형변환 오류로 인한 프로그램 비정상 종료 (ValueError)
     * **원인: input_chicken() 함수에서 중량, 단백질, 가격을 입력받을 때 사용자가 실수로 문자열을 입력하면 int()나 float() 형변환 과정에서 예외가 발생하여 프로그램이 강제 종료됨.  
     * **해결: 데이터 입력 로직 전체를 try-except ValueError 구문으로 감싸 예외가 발생하더라도 튕기지 않고 경고 메시지를 출력한 뒤 메인 메뉴로 안전하게 복귀하도록 처리함.
       
  2. **문제 2: 초기 실행 시 데이터 파일 부재로 인한 구동 실패 (FileNotFoundError)
     * **원인: 프로그램 시작과 동시에 기존 데이터를 불러오는 load_from_file() 함수가 실행되는데, 프로그램을 처음 구동하여 chicken_data.txt 파일이 디렉토리에 존재하지 않아 예외가 발생함.
     * **해결: 파일 읽기 블록을 try-except FileNotFoundError 구문으로 설계하여, 파일이 없는 초기 상태일 경우 에러 대신 안내 메시지를 띄우고 시스템이 정상 시작되도록 예외를 우회함
    
  3. **문제 3: 직접 타이핑 과정에서 발생한 괄호 및 따옴표 누락 (SyntaxError)
     * **원인: 복사 붙여넣기 금지 조항에 따라 GitHub 환경에서 직접 코드를 하나하나 입력하다가, int(input())처럼 중첩된 괄호를 하나만 닫거나 with open() 내 파일 이름의 닫는 따옴표를 누락하여 구문 오류가 발생함.
     * **해결: 에디터의 실시간 코드 하이라이팅(빨간 줄) 기능을 확인하고, 열린 괄호와 따옴표의 개수가 닫히는 쌍과 정확히 일치하는지 전수 검사하여 누락된 문자를 모두 보완함.
     * 
  4. **문제 4: 메뉴 선택 대입 연산자 오타로 인한 제어 흐름 오류 (NameError)
     * **원인: while True 루프 내부에서 사용자에게 메뉴 번호를 입력받아 저장할 때, 대입 연산자 = 대신 비교 연산자 ==를 잘못 사용하여 입력값이 변수에 정상적으로 할당되지 못함.
     * **해결: 값의 할당을 담당하는 단일 등호(=)로 코드를 수정하여 menu_choice 변수에 사용자가 입력한 번호가 정상 저장되고 하단 if-elif 분기문이 유기적으로 동작하도록 해결함.
